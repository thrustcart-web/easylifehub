> آخر تحديث: 2026-11-03
> الملف ده بيشرح **إزاي الموقع بيكبر لوحده** من غير ما تعمل أي حاجة.

## 1) ليه مش 50 مقال في اليوم؟

سؤال منطقي، والإجابة المختصرة: **لأنه هيدمّر المشروع مش هيكبّره.**

| الحد | الرقم | 50/يوم |
|---|---|---|
| مخزون المواضيع | كان 2,561 → **دلوقتي 7,135** | كان هيفنى في 51 يوم |
| سياسة جوجل "Scaled Content Abuse" | رسمية من تحديث مارس 2024 | ❌ deindexing |
| شروط Amazon Associates | بتمنع المحتوى المُولَّد بكميات | ❌ قفل الحساب + مصادرة العمولات |
| Blogger API | ~10,000 طلب/يوم، والسقف التجريبي ~30–50 بوست/يوم | ❌ تعليق API بدون استئناف |

**العقوبة الحقيقية مش "ترتيب قليل"** — العقوبة إن الموقع يفضل شغال وإنت شايفه،
بس **صفر ظهور في جوجل = صفر ترافيك = صفر فلوس**. وحساب أمازون بيتقفل والعمولات المتراكمة بتتمصادر.

## 2) خطة النمو المتدرج (Ramp-Up) — شغالة لوحدها

النظام **بيزوّد الإنتاج بنفسه** حسب عمر المدونة. مفيش أي تعديل مطلوب منك.

| من يوم | مقالات/يوم | الإجمالي التراكمي |
|---|---|---|
| 0 → 9 | **3** | 30 |
| 10 → 29 | **4** | 110 |
| 30 → 59 | **5** | 260 |
| 60+ | **6** (السقف) | **~180/شهر** |

### مكان الإعداد في الكود

`config.json`:

```json
"ramp": {
  "enabled": true,
  "stages": [
    { "day": 0,  "posts_per_day": 3 },
    { "day": 10, "posts_per_day": 4 },
    { "day": 30, "posts_per_day": 5 },
    { "day": 60, "posts_per_day": 6 }
  ]
}
```

### إزاي النظام بيحسب "عمر المدونة"؟

أول تشغيل بيكتب التاريخ في `data/ramp.json`:

```json
{ "day0": "2026-11-03" }
```

الملف ده **بيتعمل commit** مع الريبو، فالتاريخ ثابت ومش بيبدأ من جديد.
لو حبيت تبدأ العد من تاريخ تاني، عدّل `day0` يدويًا.

### تشوف إنت فين دلوقتي

```bash
python3 main.py --ramp
```

الخرج:

```json
{
  "day": 0,
  "posts_per_day": 3,
  "hard_cap": 6,
  "keyword_rows": 7135,
  "niches": 28,
  "years_of_content_at_current_rate": 6.5
}
```

> **مهم:** الـ workflow بقى **مبعتش** `--count` ثابت. لو بعت رقم،
> الرقم بيتطبّق (لكن مش أعلى من 6). لو سبته فاضي، الـ ramp هو اللي يقرر.
> عشان كده **احذف الـ Variable `DAILY_POSTS`** من إعدادات الريبو — وجودها بيجمّد العدد على 3 للأبد.

## 3) مخزون المواضيع: 7,135 موضوع في 28 قسم

### الأرقام

| | قبل | بعد |
|---|---|---|
| صفوف `keywords.csv` | 2,561 | **7,135** |
| الأقسام | 18 | **28** |
| عائلات قابلة للمقارنة | — | **695** |
| يكفي لمدة | 1.4 سنة @ 3/يوم | **6.5 سنة @ 3/يوم** |
| | 0.6 سنة @ 6/يوم | **3.3 سنة @ 6/يوم** |

### الأقسام الجديدة (10)

```
health & wellness      · office & school supplies · fashion & accessories
photography & video    · gaming                   · food & pantry
home decor             · security & safety        · crafts & hobbies
laundry & storage
```

### الأداة اللي بتولّد المواضيع

`tools/expand_keywords.py` — **حتمية (deterministic)**: نفس الـ seed بيطلع نفس الناتج بالبايت.

```bash
python3 tools/expand_keywords.py --stats      # تقرير عن المخزون الحالي
python3 tools/expand_keywords.py --dry-run    # هيزوّد إيه من غير ما يكتب
python3 tools/expand_keywords.py              # يطبّق الزيادة
```

**الأداة مش بتنسخ وتلزق.** هي عندها:
- كتالوج 544 منتج حقيقي مقسّمين على عائلات (كل عائلة فيها منتجين أو أكتر — وده اللي بيخلي المقارنات ممكنة)
- 36 نمط جملة بنفس أشكال الملف الأصلي
- وعي بالجمع/المفرد (`is a yoga mat` مش `is an adjustable dumbbells`)
- فحص ضد التكرار مع الموجود

### لو عايز تزيد أكتر

عدّل `CATALOG` في `tools/expand_keywords.py` وأضف عائلات جديدة، بعدين شغّل الأداة تاني.
القاعدة الوحيدة: **كل عائلة لازم يكون فيها منتجين أو أكتر** عشان المقارنات تشتغل.

## 4) صفحة الأقسام (Categories Hub)

كل تشغيل بيعمل rebuild لـ `content/categories/index.html`:
- 28 كارت قسم مع أيقونة ووصف وعدد المواضيع
- روابط `label search` لكل قسم
- بيتحدّث أوتوماتيك — مش محتاج تلمسه

### إزاي بتنشر على بلوجر؟

`Code.gs` فيه دالة `syncCategoryPage()`:
1. بتجيب الملف من GitHub raw
2. بتحوّل الروابط النسبية لمطلقة (`/search/label/X` → `https://yourblog.blogspot.com/search/label/X`)
3. بتعملها **Page** (مش Post) — فالصفحات **مش بتتحسب ضمن معدل النشر**، يعني مفيش أي خطر سبام
4. بتشتغل تلقائي بعد كل نشر + من `testConnection()`

### خطوة واحدة مطلوبة منك (اختيارية بس مهمة)

بعد ما الصفحة تتعمل، ضيفها للقايمة:

> **Blogger → Layout → Pages gadget → اختار "Browse All Categories" → Save**

## 5) الروابط الداخلية (Internal Links)

### كل مقال فيه دلوقتي:

```html
<div class="cat-nav">
  <a href="/search/label/Security%20%26%20Safety">🔒 More in Security & Safety</a>
  <a href="/p/categories.html">All categories →</a>
</div>
```

### وقسم "Related reading" بيتعبّى **live وقت النشر**:

```html
<div class="related" data-related="1"></div>
```

ليه فاضي في الملف؟ لأن **المقالات اللي جاية لسه مش موجودة** وقت كتابة المقال ده.
`Code.gs` بعد ما ينشر المقال:
1. بيسأل Blogger API عن آخر المقالات بنفس الـ label
2. بيستثني المقال نفسه
3. بيحط 4 روابط وبيعمل `PUT` للمقال

**النتيجة:** شبكة روابط داخلية حقيقية — وده اللي بيخلي جوجل يفهم إن الموقع "سلطة" في المجال مش مجرد كومة صفحات.

## 6) إصلاحات جودة اتعملت على الطريق

دي مشاكل كانت هتبقى كارثية على الموقع الحقيقي، والمحاكاة هي اللي كشفتها:

| المشكلة | الأثر لو سبناها | الإصلاح |
|---|---|---|
| **2,513 عنوان مكرر** في محاكاة 3 سنين | duplicate content → deindex | محرك عناوين جديد بياخد الزاوية (audience/budget/feature) + فحص تصادم ضد كل العناوين السابقة |
| **رابط أمازون بيتبني من الجملة الكاملة** (`what to check before buying a torque wrench`) | كل الروابط تكسر = **صفر عمولات** | `clean_search_term()` بيبني الرابط من اسم المنتج بس |
| `LEVOIT Air Purifier Core 300` → `Core 3` | عناوين غلط لمنتجاتك الحقيقية | حماية أرقام الموديلات في `extract_base()` |
| `A Air Fryer` بدل `An Air Fryer` | إنجليزي مكسّر في كل عنوان | `_article()` بقى بيحكم على أول صوت في الجملة مش آخر كلمة |

| `Is A Adjustable Dumbbells Worth It?` | جمع/مفرد غلط | وعي بالجمع في `_article()` و `expand_keywords.py` |
| عنوان المقال مش بيطابق الكلمة المفتاحية | تضليل للقارئ وجوجل | `_variants_for()` بيختار صف بنفس نوع القالب |
